Visual ruler for repeated Crystal Family Guide components

This page is the literal HTML/CSS reference required by EDITORIAL-PAGE-VISUAL-STANDARD.md §10 ("Component Kit"). It demonstrates the reusable patterns Claude Code should apply when normalizing completed Crystal Family guides — it is an implementation reference, not a second canonical visual authority and not a public page.

Every component below is built from the existing shared .fg- classes already used on the live Copper Minerals, Calcite, Feldspar, Quartz, Agate, Jasper, Fluorite, and Garnet guides. No shared family-guide CSS was added, duplicated, renamed, or edited to build this kit; the only new CSS is the kit-page chrome and a clearly marked .kit-demo-fg override block that previews the now-final numeric spacing and type-scale values on top of those same shared classes — see the handoff report for exactly what each override differs from in current live/per-guide CSS. Content shown is representative/placeholder; no approved family-guide copy was rewritten to populate it, and specimen photography reused here is existing approved family-guide imagery, not new photography.

AHero & Section Anatomy

Hero convention per §6.1: eyebrow CRYSTAL FAMILY, title [Stone] Family Guide, contained in the bounded white .fg-hero card at moderate scale — never full-bleed. The eyebrow identifies the page category without redundantly repeating "Family Guide" immediately above a title that already contains those words; do not shorten the title to only the family name. Hero module structure itself is already correct and is not a redesign target (§2); only the eyebrow-copy and title-size normalization below apply. Below the hero: heading → optional purpose-setting introduction → module, with two distinct internal-spacing rules per §8.2 — heading→intro is 14–16px, intro→first module is 24–26px. Major-section separation is a separate, larger rule — 60–64px desktop / 44–48px at ≤900px — and is what visibly separates one editorial idea (this whole composition) from the next.

CCard Heading & Label System

One normalized hierarchy, reused everywhere rather than competing per-guide heading treatments: a small-caps or approved eyebrow/label, with a bold or clearly emphasized card/module name beneath it (§10). DImage Wells

Every specimen well is white, uses object-fit: contain, and keeps visible breathing room on all four sides — never cropped, stretched, or distorted. Standard specimen wells hold to 170–190px desktop / 130–170px mobile (§8.2); this height is capped regardless of column count, it never grows just because a grid collapses. Different module roles legitimately use different well proportions: a standard specimen-card well is not forced to match a compact teaching-module well.

HQuick View / Grid Affordance

Quick View appears only on a stone/variety browsing card that represents a valid encyclopedia-resolvable target. Interactive cards use a real <button> image well plus an explicit "Quick View →" link — the click affordance is always visible, never implied by hover alone. A stone/variety card with no linked encyclopedia entry renders with neither, so it never reads as falsely clickable. Teaching cards, comparison explanation cards, decorative modules, and non-stone editorial cards (§E and §F above) never receive Quick View at all, regardless of roster status — the distinction is categorical, not just "linked or not."

IClosing Modules — Care for It / Remember This / Watch For

Reference: Calcite's .fg-collection-grid markup, corrected here so all three panels share one visual treatment — same fill, border, radius, heading treatment, typography, padding, and visual weight. No category receives permanent visual dominance based on its label; Care for It does not get a wider or differently-filled panel merely because it is listed first. Card widths may vary according to copy length when needed to keep the three cards at approximately the same visual height — when copy lengths are naturally similar, as in this placeholder example, equal-width thirds are preferred (Fluorite/Feldspar-style equal-treatment direction). Three cards is the default; a two-card closing is allowed only when a family genuinely lacks a useful third category — never pad a third card with weak or redundant content merely for symmetry.

Care for It

Practical handling guidance — water safety, light exposure, cleaning method — stated plainly, in prose or a short list.

Remember This

One or two memorable identifying facts worth carrying away from the page.

Watch For

Common confusions, imitations, or misattributions specific to this family.

Width follows content balance, not category: this example uses equal thirds because the three sample copy lengths are naturally similar. When one category's approved copy runs meaningfully longer or shorter, adjust that card's width instead — the goal is matched visual height across the row, not a rule that any one card must always be wider or narrower.
Mobile: resize to ≤900px — the three-column row stacks to one full-width card per row. All three cards keep the same fill, border, radius, heading treatment, and type scale they use on desktop; none becomes a narrow vertical strip and none loses its equal treatment to become dominant.

An optional closing or reflective line can follow the cards, using this same italic treatment.

JEditorial Navigation Pill

One pill family, two semantic variants — not two unrelated pill systems. Both variants share the same .fg-copper-pill base (§11): 39px tall, 22px horizontal padding, 13px/500 Jost, no letter-spacing/uppercase, 999px radius, content-sized width, and the same hover/focus quality. The difference is semantic, not decorative: --explore is for forward/deeper navigation (Explore family stones, explore a related mineral set) and may use the stronger outlined/accent treatment; --return is for back-navigation (Return to Crystal Families) and may use the quieter filled/secondary treatment. Do not invent a third variant or swap treatments for visual variety. For ordinary family-guide closing use, Return to Crystal Families remains the expected pill — show only the navigation action(s) the page actually needs, not both by default. The Return to Crystal Families pill is already standardized and is not a redesign target (§2) — preserve its existing treatment exactly. See report for the one shared-CSS note this surfaced.

  
Both buttons above share identical height, radius, padding, and typography — only fill/border color and label communicate the forward-vs-return role. That shared geometry, not a distinct component per variant, is what makes this one pill family.
KResponsive Behavior

Every component on this page inherits its responsive behavior from the shared breakpoints already in styles.css (≤900px tablet/intermediate, ≤600px mobile), layered with the .kit-demo-fg overrides above. Desktop and tablet use the appropriate approved grid column count for each module (a 4-up card grid moves to 2-up at ≤900px, for example). At the mobile breakpoint, stone/variety browsing grids remain 2 columns — they do not collapse to 1 oversized card per row — and specimen image-well height stays capped at 130–170px regardless of column count, so images never enlarge just because the grid narrows.
